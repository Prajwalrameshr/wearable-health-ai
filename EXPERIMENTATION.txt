SECTION 1 — PROJECT OVERVIEW
================================================================================

1.1 Project Name & High-Level Description
The system is named "Wearable Health AI" (also referenced in repository 
manifests as "FINAL-YEAR-PROJECT"). It is an end-to-end Python-based machine 
learning framework and interactive Web application designed to process, 
preprocess, model, and visualize longitudinal wearable physiological signal 
data (heart rate, heart rate variability, blood oxygen saturation, sleep 
duration, physical activity, blood pressure) across multi-month user timelines.

1.2 The Core Research Problem
Longitudinal physiological wearable data collected from consumer devices 
presents unique analytical challenges:
- High Inter-Individual Variability: Baseline physiological signals (e.g., 
  resting heart rate, resting HRV) vary significantly across individuals due to 
  age, sex, genetics, and baseline fitness. A raw resting heart rate of 75 bpm 
  may indicate physiological strain for an athlete but perfect baseline recovery 
  for a sedentary individual.
- Non-Stationary Time Series Dynamics: Physiological signals exhibit diurnal, 
  weekly, and seasonal drift, acute stress spikes, and gradual recovery patterns.
- High Noise & Missing Data: Wearable sensors frequently drop data due to 
  motion artifacts, improper sensor positioning, battery exhaustion, or 
  intermittent user compliance.
- Absence of Gold-Standard Labels: Continuous free-living wearable data lacks 
  frequent clinical diagnostic labels. Unsupervised state discovery must infer 
  latent physiological states without ground-truth supervisory signals.

1.3 Rationale for Core Architectural Choices
- Personalization via Baseline Deviations: To eliminate static baseline 
  differences across users, the system computes personalized 7-day causal 
  rolling baselines per individual. Signals are transformed into relative 
  deviations (e.g., hr_dev = resting_hr_bpm - baseline_hr).
- Latent Physiological State Discovery: Rather than predicting raw discrete 
  diagnoses, the system groups physiological deviation patterns into latent 
  interpretable states: "Recovery" (elevated HRV, low resting HR, adequate sleep), 
  "Baseline" (normal homeostasis), and "Strain" (depressed HRV, elevated resting HR, 
  sleep deficit).
- Temporal Sequence Modeling: Hidden Markov Models (HMM) are introduced to model 
  state persistence and multi-day transition probabilities, enforcing temporal 
  coherence over static daily clustering predictions.
- Explainability: A dual explainability framework is implemented: (1) model-native 
  GMM feature attributions based on component mean deviations, and (2) a 
  surrogate Random Forest model providing SHAP-like feature importance vectors 
  for UI rendering.
- Streamlit Web Interface: A multi-page Streamlit web dashboard (`app/main.py`) 
  provides visual analytics, interactive metric adjustments, risk scoring, 
  surrogate SHAP attributions, cohort benchmarking, and action recommendations.

1.4 System Scope & Non-Clinical Disclosure
CRITICAL SCIENTIFIC SCOPE STATEMENT:
This software system and its underlying experiments represent a METHODOLOGICAL 
BENCHMARK FOR WEARABLE PHYSIOLOGY ANALYTICS. It is NOT a clinical diagnostic 
system, medical decision support tool, or disease prediction framework. All 
latent states ("Recovery", "Baseline", "Strain") are unsupervised mathematical 
cluster interpretations, NOT medically validated clinical diagnoses.

SECTION 2 — RESEARCH OBJECTIVE & QUESTIONS
================================================================================

2.1 Research Objective
The objective of this research is to evaluate whether transforming raw 
physiological signals into personalized baseline deviations and composite 
severity scores improves unsupervised latent health state discovery and 
temporal sequence stability compared to standard unnormalized physiological 
baselines.

2.2 Core Comparison Dimensions
The experimental framework evaluates five distinct methodological dimensions:
1. Signal Representation: Raw physiological metrics (B0, B2) vs. Personalized 
   baseline deviations (B3, B4, B5, B6).
2. Model Family: Rule-based thresholding (B1) vs. Hard centroid clustering (KMeans; 
   B2, B3) vs. Soft probabilistic density estimation (GMM; B4, B5, B6).
3. Temporal Dynamics: Static daily observation clustering (B0–B4) vs. Dynamic 
   sequential state modeling (HMM; B5, B6).
4. State Discretization: Hard discrete state assignment (B5 Categorical HMM) vs. 
   Continuous soft probability distribution modeling (B6 Soft Gaussian HMM).
5. Generalizability: Chronological holdout performance vs. Subject-independent 
   (unseen user) cross-validation performance.

2.3 Formulated Research Questions
Potential research questions derived from the implemented experiments:
- RQ1: Does evaluating GMM clustering on personalized baseline deviations yield 
  significantly higher clustering separation (Silhouette, Davies-Bouldin, 
  Calinski-Harabasz) on unseen subjects compared to clustering raw physiology?
- RQ2: Does incorporating 7-day rolling slopes and composite severity score 
  normalization improve cluster separation in feature space?
- RQ3: Does sequential temporal modeling via Hidden Markov Models improve state 
  persistence and reduce high-frequency daily state chatter compared to static 
  daily GMM classification?
- RQ4: Does fitting a continuous Gaussian HMM over soft GMM posterior probability 
  vectors preserve distribution uncertainty without degrading into state 
  collapse compared to a discrete Categorical HMM?

SECTION 5 — DATA PREPROCESSING & CAUSAL ENGINEERING
================================================================================

5.1 Missing Value Handling (`handle_missing`)
- Causal Forward Fill: Missing daily physiological values are causally forward-filled 
  (`ffill()`) within each individual user timeline.
- Zero Backward Fill: Backward filling (`bfill()`) was COMPLETELY REMOVED to eliminate 
  future data leakage.
- Causal Initial Prefix Imputation: Any unobserved prefix observations prior to a 
  user's first valid reading are filled using static physiological baseline defaults 
  (`PHYSIOLOGICAL_FALLBACK_DEFAULTS`: resting_hr=70, hrv=50, spo2=98, sleep=7, steps=5000) 
  or training-derived cohort statistics. Full-column dataframe median fallback was eliminated.

5.2 Causal Outlier Capping (`remove_outliers`)
- Non-Causal Global IQR Capping Removed: Global dataset-wide static IQR bounds were 
  replaced.
- Expanding Causal Window: Outlier thresholds (1.5 × IQR) are computed per user 
  using an expanding causal window containing only historical observations up to time t 
  (history $\le t$). Outliers are capped at `[Q1 - 1.5*IQR, Q3 + 1.5*IQR]`.

5.3 Personalized Baseline Calculation (`compute_baseline`)
- Rolling Window: 7-day causal backward-looking rolling window.
- Mandatory Warm-Up Requirement: `min_periods=7` is strictly enforced. Days 1 through 6 
  of a user's timeline are marked `baseline_valid = False` because 7 full days of history 
  are required for a stable baseline.
- Early Warmup Fallback: For Days 1–6, expanding means up to day t are used for 
  temporary feature computation, but `baseline_valid` tracks warm-up status.

5.4 Temporal Slopes (`compute_temporal_features`)
- Causal Rolling Slope: Computed per user using a 7-day backward window via `np.polyfit`.
- Features: `hr_dev_slope_7d`, `hrv_dev_slope_7d`, `sleep_dev_slope_7d`, `steps_dev_slope_7d`.

5.5 Composite Severity Representation (`compute_severity`)
- Standardized Deviations: `hr_dev_z`, `hrv_dev_z`, `sleep_dev_z`, `steps_dev_z`, `spo2_dev_z`.
- Severity Score: `severity_score = sum(|z_devs|)`. Quantifies global homeostatic disruption.
- Cluster Columns (`CLUSTER_FEATURE_COLUMNS`): `["hr_dev", "hrv_dev", "sleep_dev", "severity_score"]`.

5.6 Feature Scaling & Split Mechanics
- Train-Only Scaling: `StandardScaler` is fitted strictly on the training set (`train_df`). 
  Validation (`val_df`), testing (`test_df`), and inference sets are transformed using the 
  pre-fitted scaler. The fitted scaler is persisted to `models/scaler.pkl`.
- Chronological Split (`chronological_split`): Per-user time-series split preserving 
  date order: 70% Train (38,400 rows), 15% Val (8,100 rows), 15% Test (8,700 rows).
- Subject-Independent Split (`subject_independent_split`): 5-fold `GroupKFold` split by `user_id`. 
  Splits 300 users into 240 train users and 60 test users per fold with ZERO user overlap.

SECTION 6 — DATA LEAKAGE AUDIT & RESOLUTIONS
================================================================================

All identified leakage sources were rigorously audited, corrected, and verified with 
automated unit tests:

1. LEAKAGE ISSUE: Backward Fill (`bfill()`) in missing value imputation.
   - WHY IT WAS A PROBLEM: Propagated future physiological readings backward in time to fill past missing days.
   - HOW FIXED: Removed `bfill()`. Implemented causal `ffill()` and initial prefix physiological defaults.
   - VERIFICATION: `tests/test_preprocessing.py::test_handle_missing_causal_no_bfill` (PASSED).

2. LEAKAGE ISSUE: Future Information in Outlier Capping.
   - WHY IT WAS A PROBLEM: Computed global IQR bounds over the entire 6-month timeline.
   - HOW FIXED: Replaced with per-user expanding causal window ($t' \le t$).
   - VERIFICATION: `tests/test_preprocessing.py::test_remove_outliers_causal` (PASSED).

3. LEAKAGE ISSUE: Scaler Fitted on Full Dataset.
   - WHY IT WAS A PROBLEM: Mean and standard deviation of held-out test data leaked into training features.
   - HOW FIXED: Scaler fitted strictly on `train_df`.
   - VERIFICATION: `tests/test_preprocessing.py::test_fit_transform_scaler_split` (PASSED).

4. LEAKAGE ISSUE: Baseline Calculation Warm-Up Absence.
   - WHY IT WAS A PROBLEM: Uncalibrated Days 1–6 were treated as fully valid baselines.
   - HOW FIXED: Enforced `min_periods=7` warm-up requirement and `baseline_valid` flag.
   - VERIFICATION: `tests/test_preprocessing.py::test_compute_baseline_warmup` (PASSED).

5. LEAKAGE ISSUE: Test-Set HMM Model RefITTING.
   - WHY IT WAS A PROBLEM: HMM models B5 and B6 were invoking `.fit()` directly on test set sequences.
   - HOW FIXED: HMM models are fitted ONLY on `train_labeled` sequences. Test set evaluation passes `fitted_model` for inference only (`.score()`, `.predict()`).
   - VERIFICATION: `tests/test_models.py::test_hmm_never_fits_on_test_data` (PASSED).

6. LEAKAGE ISSUE: Multi-User HMM Transition Contamination.
   - WHY IT WAS A PROBLEM: Concatenating multi-user time series into a single array caused HMM transitions across user boundaries (User A Day 184 -> User B Day 1).
   - HOW FIXED: `build_hmm_sequences` explicitly extracts per-user sequence lengths array `lengths` and passes it to `hmmlearn`.
   - VERIFICATION: `tests/test_models.py::test_hmm_sequence_length_isolation` (PASSED).

7. LEAKAGE ISSUE: Full-Column Median Fallback in Missing Value Imputation.
   - WHY IT WAS A PROBLEM: Taking `df[col].median()` over unpartitioned data allowed test set values to influence past prefix imputation.
   - HOW FIXED: Updated `handle_missing()` to accept `cohort_stats` fitted on train data or use static physiological fallback constants.
   - VERIFICATION: `tests/test_preprocessing.py::test_causal_initial_imputation_no_future_leakage` (PASSED).

8. LEAKAGE ISSUE: Subject-Independent Split User Overlap.
   - WHY IT WAS A PROBLEM: Random k-fold splitting would put observations from the same user into both train and test splits.
   - HOW FIXED: Implemented `GroupKFold` grouped by `user_id`.
   - VERIFICATION: `tests/test_preprocessing.py::test_subject_independent_split_user_disjointness` (PASSED).

SECTION 8 — MODEL 2: GAUSSIAN MIXTURE MODEL (GMM)
================================================================================

- Rationale: Provides soft probabilistic density estimation over continuous physiological deviation space, yielding continuous posterior probability vectors $P(S = s_i \mid \mathbf{x}_t)$ for each state.
- Module: `src/gmm.py` (`run_gmm_pipeline`, `select_gmm_components`, `load_gmm_model`, `save_gmm_model`).
- Component Selection: Evaluates $k \in \{2, 3, 4, 5\}$ using Bayesian Information Criterion (BIC) and Akaike Information Criterion (AIC) on `scaled_train`.
  - Selected $k = 3$ ($\text{BIC} = 142105.4$).
- Latent State Interpretation:
  - Cluster 0: "Recovery" (Low resting HR deviation, elevated HRV deviation, positive sleep duration)
  - Cluster 1: "Baseline" (Near-zero deviations across all physiological parameters)
  - Cluster 2: "Strain" (Elevated resting HR deviation, depressed HRV deviation, negative sleep deviation, high severity score)
- Feature Attribution (`compute_gmm_native_feature_importance`): Model-native attribution computed from absolute differences in GMM component Gaussian means normalized across components.
- Model Persistence: Serialized to `models/gmm.pkl`.
- Separation of Training & Inference: `run_gmm_pipeline` accepts `fitted_model`. Inference loads `models/gmm.pkl` and transforms test/inference data via `.predict()` and `.predict_proba()` without refitting.
- Baseline Evaluation Results (Chronological Test Split):
  - B4 (GMM Personalized Deviations): Silhouette = `0.1944`, DB = `1.4211`, CH = `2284.14`
- IMPORTANT COMPARATIVE NOTE: GMM (B4 Silhouette = `0.1944`) is NOT automatically superior to KMeans (B3 Silhouette = `0.2260`) purely on static distance-based Silhouette score. GMM's advantage lies in producing continuous posterior probability distributions for downstream probabilistic modeling.

SECTION 9 — MODEL 3: HIDDEN MARKOV MODEL (HMM)
================================================================================

- Rationale: Introduced after GMM to model sequential temporal dynamics, state persistence, and multi-day state transition probabilities across daily wearable timelines.
- Module: `src/hmm_model.py` (`train_hmm`, `decode_states`, `run_hmm_pipeline`, `run_soft_probability_hmm`, `load_hmm_model`, `save_hmm_model`).
- Multi-User Sequence Isolation: Uses `build_hmm_sequences` to format input matrices into 2D stacked arrays while maintaining an explicit `lengths` list containing each user's exact sequence length.
- Training vs. Inference Protocol:
  - Training: `train_hmm` / `run_soft_probability_hmm` fits `CategoricalHMM` or `GaussianHMM` strictly on `train_labeled` sequences.
  - Inference: `decode_states` / `run_soft_probability_hmm` accepts `fitted_model` and decodes hidden state sequences on `test_labeled` sequences via Viterbi (`.predict()`) and log-likelihood scoring (`.score()`). `.fit()` is NEVER called during test evaluation.
- HMM Variants Evaluated:
  1. B5 (Hard Categorical HMM): Takes discrete GMM cluster integers $\{0, 1, 2\}$ as observations.
  2. B6 (Soft Gaussian HMM): Takes continuous GMM posterior probability vectors $[P(\text{Recovery}), P(\text{Baseline}), P(\text{Strain})]$ as observation vectors.

SECTION 11 — B6 MODEL FAILURE & DEGENERACY ANALYSIS
================================================================================

11.1 Investigation Background
B6 (Soft-Posterior Gaussian HMM) was designed to model continuous temporal transitions directly over GMM posterior probability vectors $[P(\text{Recovery}), P(\text{Baseline}), P(\text{Strain})]$ without discarding probability distribution uncertainty via hard integer discretization.

11.2 Empirical Failure Discovery
Deep empirical inspection of the actual test set predictions (`scratch/inspect_b6_degeneracy.py`) revealed that B6 SUFFERED COMPLETE MODEL COLLAPSE:
- Unique States Used: Only 1 state out of 3 (State 1 only).
- State Occupancy Counts:
  - State 0: 0 observations (0.00%)
  - State 1: 8,700 observations (100.00%)
  - State 2: 0 observations (0.00%)
- Per-User Unique States: Min = 1, Max = 1, Mean = 1.00 state/user. Every single user timeline was decoded into a single unbroken run of State 1.
- State Run Durations: 300 runs total (1 run per user), Min = 29 days, Max = 29 days, Mean = 29.00 days.
- Daily Transition Rate: 0.0000 transitions / day (zero state transitions produced).
- Transition Stability: 1.0000 (100.0%).
- Transition Matrix ($A$):
  $$\begin{pmatrix} 0 & 1 & 0 \\ 0 & 1 & 0 \\ 0 & 1 & 0 \end{pmatrix}$$

11.3 Mathematical Root Cause of Collapse
When `GaussianHMM` was fitted directly on continuous GMM posterior probability vectors, the test set GMM posterior vectors were extremely sharp/concentrated (posterior entropy = 0.0000 bits). The Baum-Welch algorithm converged to a degenerate single-state Gaussian component where State 1 had zero covariance and an absorbing transition row ($A_{i,1} = 1.0$ for all $i$).

11.4 Artifact Verification
- 29.00-Day Mean Duration Artifact: The test split per user is exactly 29 days long (15% of 184 days = 27.6 -> 29 days). Because B6 never transitioned out of State 1, every user's test timeline produced a single run of 29 days. The 29.00-day mean duration is simply the length of the test sequence per user.
- 100% Transition Stability Artifact: B6's reported "100% stability" is a trivial artifact of zero state transitions.

11.5 Scientific Conclusion
B6 MUST BE REPORTED AS A FAILED / DEGENERATE EXPERIMENT. It must NEVER be presented as a successful proposed method in an IEEE paper. Retaining this negative result provides valuable scientific insight into the numerical instability of continuous Gaussian HMMs over low-entropy GMM posterior vectors.

SECTION 13 — A-G COMPONENT ABLATION STUDY
================================================================================

13.1 Ablation Study Pipeline & Results
The genuine component ablation study evaluates cumulative feature and modeling additions starting from raw physiology up to soft HMM decoding on the held-out test split:

| Step | Configuration | Test Silhouette | Delta vs Prev | Key Finding |
| :---: | :--- | :---: | :---: | :--- |
| **A** | Raw Physiology (GMM) | 0.1724 | Baseline | Raw physiological signals only (`resting_hr`, `hrv`, `sleep`, `steps`). |
| **B** | + Personalized Baseline Deviations | 0.1509 | -0.0214 | Adding deviation features (`hr_dev`, `hrv_dev`, `sleep_dev`, `steps_dev`) without severity normalization. |
| **C** | + 7-Day Rolling Slopes | 0.1118 | -0.0391 | Adding 7-day rolling slopes (`hr_dev_slope_7d`, etc.) increases feature dimensionality. |

SECTION 16 — STATISTICAL SIGNIFICANCE TESTING
================================================================================

16.1 Wilcoxon Signed-Rank Test Results
A paired two-sided Wilcoxon signed-rank test was conducted on the 5 paired subject-independent fold Silhouette scores:
- Test Statistic ($W$): `0.0`
- Exact Two-Sided $p$-value: **`0.0625`**
- Significance Threshold ($\alpha$): `0.05`

16.2 STATISTICAL SIGNIFICANCE VERDICT
RIGOROUS INTERPRETATION: $p = 0.0625 > 0.05 \implies$ **NOT STATISTICALLY SIGNIFICANT** at the standard 5% significance level ($\alpha = 0.05$).

16.3 Mathematical Boundary Analysis
For a two-tailed Wilcoxon signed-rank test with $N = 5$ paired observations where all 5 differences are strictly positive ($W = 0.0$), the minimum achievable exact $p$-value is:
$$p_{\min} = \frac{1}{2^{5-1}} = \frac{1}{16} = 0.0625$$
Consequently, a 5-fold cross-validation setup is MATHEMATICALLY INCAPABLE of demonstrating statistical significance at $\alpha = 0.05$ regardless of effect size. At least $N \ge 6$ folds are required to achieve $p < 0.05$ ($p_{\min} = 0.03125$).

16.4 Exact Cohen's d Effect Size
- Exact Formula: $d = \frac{\bar{d}}{s_{\text{diff}}} = \frac{0.033920}{0.007355} =$ **`4.6119`**
- CRITICAL STATISTICAL WARNING: While $d = 4.6119$ represents a large standardized effect size, $N = 5$ is an extremely small sample size. Effect size MUST NOT be used as a replacement or surrogate for statistical significance.
